# Разработка встроенных приложений NSMP

Этот репозиторий содержит UI-фреймворк `@minitwiks/nsmp-vue-components`
на Vue 3 и Ant Design Vue. Правила ниже помогают создавать приложения-потребители.
Новое приложение создавай в отдельном каталоге; исходники библиотеки не изменяй.
Пути `src`, `docs`, `demo`, `tests` ниже относятся к библиотеке, 
если явно не указан репозиторий приложения.

## Источники и версии

- Генератор и шаблон: https://github.com/ErilovNikita/create-nsmp-embedded-app
- UI-документация: https://erilovnikita.github.io/nsmp-vue-components/
- Иконки: https://github.com/ErilovNikita/nsmp-icons
- Прикладной пример: https://github.com/ErilovNikita/SDKeysWork
- Перед использованием проверяй package.json и lockfile приложения,
  установленные версии UI/Vue/Antd/js-api и peer dependencies. Не переноси
  API из другой версии без проверки; опубликованные exports/d.ts определяют
  доступный потребителю контракт.
- В исходниках библиотеки проверяй `src/index.ts`, `src/utils.ts`, barrels,
  `src/components/<Name>/types.ts` и SFC: defaults, emits, slots, expose,
  forwarding. Наследование Antd props не гарантирует поддержку всех его slots.
- Документация — `docs/`, композиции — `demo/src/`, поведение — `tests/unit/`.
  SDKeysWork используй как источник сценариев, проверяя код перед переносом.

## Создание и bootstrap приложения

- Для нового проекта используй генератор `create-nsmp-embedded-app` и его
  актуальные инструкции. Выбирай UI и utilities по задаче; они опциональны.
  Не переписывай готовый bootstrap, dev proxy и упаковку без необходимости.
- Шаблон инициализирует `@minitwiks/js-api` через initializeJsApi до mount
  и предоставляет экземпляр через `app.provide('jsApi', jsApi)`.
  Сохраняй эту последовательность; типы и методы сверяй с установленным js-api.
  Ошибка инициализации должна давать понятное состояние интерфейса.
- Подключай `@minitwiks/nsmp-vue-components/style.css` в bootstrap,
  оборачивай UI в ConfigProvider. NsmpVueComponents регистрирует компоненты,
  но не создаёт provider и не загружает тему. Для глобальных a-* компонентов
  нужна регистрация Antd; локальные imports делай явно.
- При инициализации нового проекта сразу настраивай автоматическую темизацию:
  определяй текущую тему пользователя NSMP, загружай её из целевой инсталляции
  и передавай разобранные свойства в корневой `ConfigProvider` через `nsmpTheme`.
  Используй руководство [«Темизация»](https://erilovnikita.github.io/nsmp-vue-components/guide/theming)
  (`docs/guide/theming.md`) и примеры из него: получение кода темы через
  персональные настройки пользователя в модуле NSMP, загрузку через
  `/sd/jspresource` и разбор с помощью `parseNsmpTheme`.
  Способ передачи кода темы из модуля в приложение сверяй с контрактом
  инсталляции и выбранного шаблона; не подменяй определение темы фиксированным
  значением. Пока тема загружается или при ошибке используй встроенный fallback
  `blue`, сохраняя работоспособность интерфейса.
- В приложении импортируй UI только через публичные entrypoints пакета,
  utilities — из `@minitwiks/nsmp-vue-components/utils`. Source imports
  `../../../src` из demo не переноси в приложение.
- Сохраняй относительный Vite base и proxy `/sd/`, если они предусмотрены
  шаблоном. Конфигурацию окружения сверяй с его example.env.
  Любые используемые клиентом VITE_* доступны в bundle: секреты туда не помещай.

## Организация кода и NSMP-интеграция

- Отделяй NSMP services/adapters, DTO, состояние и Vue views. Следуй структуре
  созданного проекта; Pinia и router добавляй, когда они нужны задаче.
- Типизируй DTO, props, события и refs; ошибки обрабатывай как unknown
  с narrowing. Не замещай неизвестный контракт js-api через any.
- В views не дублируй запросы и преобразования DTO. Обрабатывай HTTP errors,
  unexpected responses и устаревшие ответы при смене фильтра/страницы.
- Разделяй development mocks и production интеграцию. Не представляй mock
  как подтверждение работы в NSMP. Серверные методы, UUID, атрибуты и права
  проверяй по контракту конкретной инсталляции; не выдумывай их.
- Используй utilities шаблона, если они выбраны: theme зависит от dispatch;
  environment/platform/version подключаются по необходимости. Dispatch
  и получение темы проверяй на целевой версии NSMP.
- Скрытие или disabled кнопки не заменяет проверку полномочий на сервере.

## Выбор компонентов и формы

- Сначала используй компоненты фреймворка: Table для списка, Form для
  редактирования, AttrGroup для read-only атрибутов, Tabs для разделов,
  Modal для ограниченной операции, Alert/notifications для обратной связи.
  Antd применяй для отсутствующих возможностей, сохраняя тему приложения.
- Tabs создаёт вкладки по `items`: `key` — код вкладки, `label` — её подпись.
  Содержимое каждой вкладки размещай внутри соответствующего именованного
  слота: по умолчанию имя равно `String(item.key)`, а при указанном `item.slot`
  используй его значение. Например, для `{ key: 'details', label: 'Данные' }`
  передавай содержимое через `<template #details>…</template>` внутри Tabs.
  Всё, что относится к вкладке (формы, таблицы, кнопки), должно быть в её слоте;
  обычное содержимое без именованного слота Tabs не выводит.
- Поля используют `v-model:value`; FormCheckbox/FormSwitch — `v-model:checked`.
  Обычный v-model с modelValue не является их контрактом.
- `Form :model` + `name` поддерживает binding без explicit v-model, включая
  пути-массивы. Явно переданный value/checked имеет приоритет, даже undefined;
  выбирай осознанно способ привязки каждого поля.
- Настройки control передавай через inputProps/selectProps/datePickerProps/
  rangePickerProps/checkboxProps и соответствующие props других полей.
  Attr на wrapper не обязательно попадёт во вложенный control.
- Для строковых дат задавай valueFormat через соответствующий picker props;
  без него не предполагай string вместо Dayjs. Различай single/range values.
- Валидируй форму перед сохранением. На время submit блокируй повторное
  действие; при ошибке сохраняй введённые данные и показывай сообщение.
  Закрывай modal после успешного сохранения согласно сценарию.
- Каждое модальное окно создавай в отдельном Vue-компоненте с конфигурацией
  из родительского компонента. Передавай данные и настройки (например,
  заголовок, режим работы, подписи кнопок) через типизированные props;
  состояние открытия контролируй из родителя через согласованный v-model.
  О подтверждении, отмене и результате операции сообщай родителю через
  типизированные emits. Не изменяй props напрямую и не привязывай модальное
  окно к внутреннему состоянию конкретного родителя.

## Таблицы и действия

- Указывай стабильный rowKey (например uuid/id): default — key. Не используй
  индекс страницы как идентичность объекта. Типизируй columns и данные.
- Table не загружает данные. Server pagination управляется приложением:
  current/pageSize/total, loading/error, сброс страницы при изменении фильтра
  и защита от поздних ответов. Проверь значение total по серверному контракту.
- Для выбора используй `v-model:selected-objects`; selection включён по
  умолчанию. Определи, сохраняется ли выбор между страницами и обновлениями.
  Не обещай действия над всеми найденными строками по выбору текущей страницы.
- Views и сохранение order/hidden/width — отдельная возможность Table.
  viewStorageKey делай уникальным для приложения/таблицы, при необходимости
  пользователя. Не сохраняй секретные данные в localStorage.
- Row actions и массовые действия разделяй; разрушительные операции должны
  иметь понятную область действия, подтверждение и обработку ошибки.

## Тема, иконки и встроенный UI

- У основного блока приложения не должно быть внешних и внутренних отступов
  (`margin: 0; padding: 0`). Не добавляй отступы на корневую обёртку:
  необходимые отступы уже предусмотрены компонентами библиотеки.
- Кнопки в верхней части приложения и над таблицей всегда задавай с
  `type="default"`. По возможности добавляй подходящие по смыслу иконки
  из `nsmp-icons`, используя поддерживаемый контракт `Button.icon`.
- В модальном окне основная кнопка действия («ОК», «Сохранить», «Готово»)
  всегда имеет `type="primary"`; соседние вспомогательные кнопки
  («Отменить», «Назад», «Закрыть») — `type="text"`.
- Не используй лищние заголовки и подписи; не дублируй подписи вкладок заголовками без необходимости.
- Текст темы разбирай parseNsmpTheme, не выполняй его как JavaScript.
  При загрузке проверяй HTTP status; ошибка темы не должна блокировать UI:
  сохраняй встроенный fallback blue. Источник пользовательской темы —
  интеграция приложения, а не функция UI-библиотеки.
- theme overrides и собственные CSS variables идут разными путями;
  default Button имеет отдельные variables. Проверяй конкретный результат
  вместо предположения, что theme.components перекрывает все стили.
- `Button.icon` принимает Vue-компонент из `nsmp-icons/vue` или доверенный
  SVG `?raw`. Root nsmp-icons экспортирует SVG imports/URL для img.src,
  а не SVG-разметку для v-html. Не вставляй непроверенный внешний SVG.
- Учитывай iframe, popup/modal teleports, контейнеры, clipping и изменение
  высоты. Подключай iframe-resizer child только при необходимости и согласно
  выбранной версии шаблона/пакета; не смешивай разные поколения imports.
- Проверяй узкую ширину, длинные подписи, loading/empty/error/no-permission,
  клавиатурный focus и доступные имена icon-only кнопок. Сохраняй оформление
  NSMP; точечные стили предпочтительнее глобальных переопределений .ant-*.

## Проверка результата

- Команды бери из package.json приложения. Запускай его typecheck/build;
  библиотечные demo:build/docs:build не заменяют consumer build.
- Проверяй значимую логику: validation, pending submit, пагинацию, выбор,
  ошибки и fallback темы. Визуальные изменения проверяй в браузере/iframe.
- Различай результаты typecheck, tests, browser review и проверки в NSMP.
  Отмечай не проведённые проверки и используемые версии.
- Production build шаблона может включать упаковку модулей и ZIP. Проверь
  артефакт и относительные assets. Deploy/release выполняй только когда
  публикация входит в пользовательскую задачу.
